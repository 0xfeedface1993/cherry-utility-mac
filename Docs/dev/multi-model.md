# 多型号兼容

除 MX PIXIU 75 外，App 对其他 CHERRY 键盘的支持全部来自官方驱动与升级包的逆向结果，没有真机验证。本文记录这些结论、依据和由此得出的取舍。实现在 `CherryCore/Domain/Keyboard.swift`、`KeyboardModel+Catalog.swift`（型号目录）与 `KeyboardLayout+Catalog.swift`（生成的键位图）。

## 依据

| 内容 | 来源 |
|---|---|
| 官方驱动 | CHERRY Utility 2.3.28.7 Windows 安装包，解出其中的 `app.7z` |
| 设备表（DeviceIndex、VID/PID、类型、名称） | 反汇编驱动初始化代码（0x404000–0x40a000） |
| HID 接口表（UsagePage / ReportID） | 反汇编 0x40d730 起的初始化函数 |
| 灯效表与键位 | 驱动的 `DefaultData/default_light.json`、`DefaultData0.json`、`Skin/XML/DeviceXml/keyboarddevice_<型号>.xml`、`lan_cn.xml` / `lan_en.xml` |
| 固件目录与升级包 | CHERRY 官方固件目录（`frontend.cherry.cn/goods_drive/getDriveList`）中的全部 45 个键盘升级包，MD5 与目录一致 |

驱动与升级包是 CHERRY 的版权文件，不放进仓库。

## 1. 所有键盘共用同一私有协议

驱动接口表里，**每个**键盘 PID（含 2.4G 接收器）的配置接口都是 UsagePage `0xFF1C` / Usage `0x92` / 报文 #4，Consumer 接口为 `0x000C` / #3。驱动只有一套命令实现（`0x4d9eb0` 起约 40 个函数），不按型号换协议。

| 命令 | 驱动函数 | 用途 |
|---|---|---|
| `0x01` / `0x02` | `0x4d9eb0` / `0x4da0e0` | 开始 / 结束配置 |
| `0x05` / `0x06` | `0x4dd8e0` / `0x4dd640` | 读 / 写配置空间（写入 byte7 = `0x55`） |
| `0x07` | `0x4dc2d0` | 键位表 |
| `0x1A` | `0x4ddc40` | 电量 |
| `0x1D` | `0x4de360` | 设备信息块 |
| `0x09` `0x0A` `0x0B` `0x12` `0x15` `0x1B` `0x1E` `0x1F` `0x20`–`0x29` `0x32` `0x37`–`0x3B` `0x46` `0x47` | 其余 | 宏、逐键灯光、时钟同步（`0x28`）等，本 App 未使用 |

- 分块大小由 `0x4de960` 设置：常规模式 56 字节；只有设备类型 6（MW 2.2 鼠标接收器）或手动切换的模式用 55 / 24 字节。键盘与键盘接收器（类型 8）在常规模式下与有线相同。
- 配置空间以 64 字节为一个配置档块（`n << 6`），所有型号一样。

报文格式与 PIXIU 75 的字段布局见 [HID 协议备忘](hid-protocol.md)。

## 2. 配置块字段一致，各型号只是写入范围不同

驱动写灯效与基础设置的函数 `0x500790` 先组装同一个 64 字节块：`[0]` 配置档号，`[1]` 灯效（经该型号灯效表的 `value`），`[2]` 亮度，`[3]` `4 − 速度`，`[4]` 方向，`[5]` 随机色，`[6..8]` RGB，`[0x19..]` 指示灯颜色，`[0x22..0x25]` 两级休眠。随后按 PID 决定写哪些字节：

| 写入范围 | PID | 本 App 可编辑 |
|---|---|---|
| 不写（直接返回） | `0x0077` `0x00C3` `0x00CD` `0x00CB` `0x00D2` `0x00CE` `0x01AB` `0x01AF` `0x01BB` `0xC0CE`（无背光型号） | 无灯效；可切换配置档 |
| `[0..3]` | `0x00B4`（MX 1.0 TKL 单色背光） | 灯效、亮度、速度 |
| `[0..8]`、`0x15`、`0x18`（默认分支） | 其余有线 Sonix 型号、部分接收器、MX 3.0S 宝可梦版 | 灯效全部字段，不含休眠 |
| `[0..8]`、`0x15`、`0x19..0x27` | `0x01B2` `0x01B7` `0x01B1` `0x01B4` `0x00E5` `0x00EC` `0x01C2` `0x01C3` `0x00E3` `0x00EA` `0x01F3` | 灯效全部字段；无线型号加休眠 |
| `[0..8]`、`0x15`、`0x19..0x34` | `0x01D7`（MX 3.1） | 灯效全部字段 |
| 读整块后写 `[0..0x37]`（保留 0x14/0x16/0x17） | `0x01DE` `0x01E2` `0x01E4` `0x01DA` `0x01DB` `0x01E6` `0x01E8` `0x01F7` `0x01F9` `0x01EF` `0x01F1` | 灯效全部字段 + 休眠（PIXIU 75 已真机验证） |
| 读整块后写 `[0..0x3F]`（保留 0x13/0x14/0x16/0x17） | `0x01FB` `0x0142` `0x014C` `0x014E` | 灯效全部字段 + 休眠 |

- PIXIU 99（`0x01FB`）把灯效字节的高 2 位另作他用（`effect |= x << 6`）。所有型号的灯效值都小于 `0x40`，所以 App 统一按低 6 位读写灯效、保留高 2 位。
- App 的写入是「读-改-写，只发改动字节」，再按上表限制可编辑字段，因此不会写到驱动不写的字节。同时改灯效和休眠时分两段写 `[1…8]` 与 `[0x22…0x25]`，不顺带重写中间未改动的字节。

## 3. 灯效表

`default_light.json` 按驱动 DeviceIndex 排列（PIXIU 75 = 51）。键盘用到 13 种表：

| 表 | DeviceIndex | 取值 |
|---|---|---|
| 标准 11 种 | 0 6 7 10 12 15 17 20 21 23 26 34 36 38 41 42 45 48 51 56 59 | 0 波纹、1 光谱、2 呼吸、10 霓虹、12 曲线、15 折返、18 放射、19 扩散、21 单点亮、3 常亮、8 自定义 |
| 标准 + 22 RGB 常亮 | 44（MX 8.2 Xaga） | |
| 标准 + 23 闪电 | 47（MX 3.0S 宝可梦） | |
| 标准 + 24 火焰 | 50（MX 3.0S 火龙） | |
| 标准 + 23 对战 | 53（PIXIU 75 宝可梦） | |
| 单色背光 6 种 | 4 13 14 19 | 0 波纹、2 呼吸、18 放射、21 单点亮、3 常亮、8 自定义 |
| B 型 12 种 | 52 54 60（MX 8.3、PIXIU 98、MX 8.3 Pro） | 6 波纹、7 光谱、8 呼吸、9 霓虹、5 彩虹雨、10 曲线、11 折返、0 放射、1 扩散、2 单点亮、3 常亮、4 自定义 |
| B 型 11 种 | 55（MX 10.1） | 同上，无彩虹雨 |

B 型表的「自定义」是 4、「呼吸」是 8，所以界面和自动化都按灯效的语义（名称）查表，不能用「灯效值 = 8」判断自定义灯效。

## 4. 键位图由驱动数据生成

`keyboarddevice_<型号>.xml` 的第一个面板（US）给出每个键的编号、位置和尺寸；`DefaultData0.json` 的 `KeyList[编号].DefaultAssignment` 给出键值：`0x20` 键码（修饰键在 p1 用位掩码），`0x30` Consumer（小端），`0xA0` 内部功能（Fn 等，HID 上看不到），`0xD0` 旋钮（01 逆时针 → 音量-、02 顺时针 → 音量+、04 按下 → 静音）。

`Scripts/generate-keyboard-layouts.py` 用这套规则生成 44 种键位图；同样规则生成的 PIXIU 75 布局与手工核对过的 `KeyboardLayout+PIXIU75.swift` 逐键一致（`--check-pixiu75`）。用法见 [构建与测试](building.md#键位图数据)。

## 5. 固件升级包的 6 个家族

| 家族 | 型号 | 升级程序 / 芯片 | App 支持 |
|---|---|---|---|
| Telink USB_OTA（.NET，`code_2M` + `param_128K`） | PIXIU 75（`0x01E2`）、PIXIU 75 宝可梦（`0x01F7`） | Telink B91，UsagePage `0xFFEF` #5 | 刷写 + 读回 CRC |
| EVision Sonix ISP（MFC，RCDATA 4011 = zip 内 `.hex`） | 21 个有线型号：MX BOARD 1.0/2.0S/3.0S/3.1/8.0/10.0、G80-3000、MV 3.0 等 | SN32F24xB / SN32F26x | 显示版本，提示用官方升级程序 |
| DOWNLOAD 资源（MFC） | MX 2.0/3.0S/8.2/Xaga 无线、MX-LP 2.1/6.1、K63W Pro 及其接收器 | Cortex-M（接收器含 nRF5 SDK） | 同上 |
| FIRE_WARE2 资源（x64） | MX 8.3、MX 10.1、PIXIU 98 及接收器 | 自定义容器 | 同上 |
| EVision + Telink TLSR8 | MX 2.0 无线 TLK（`0x01DE`） | 原生 EVision 工具 | 同上 |
| Nordic DFU | PIXIU 99 及接收器 | `BIN 130`×2 | 同上 |

除 Telink USB_OTA 外，其他家族的刷写协议都在各自的原生升级程序里，没有逆向，也没有真机可验证；为它们实现刷写有变砖风险，所以不做。

## 6. PIXIU 75 宝可梦版的自定义固件定义

宝可梦版 0102（168468 字节，CRC `0x2AA2487F`）与 0117 是同一套代码：gp 同为 `0x80800`，Win/Mac 模式变量 `gp+0x157` 在两个镜像中的 5 处引用一一对应，Fn 表内容相同、各被引用一次，只整体后移 `0x9C0`。

| 选项 | 0117 位置 | 宝可梦 0102 位置 | 移植方式 |
|---|---|---|---|
| F 区固定 | `0x02550` / `0x02554` | `0x027A4` / `0x027A8` | 同一条 `nds.lbugp a0, 343`；分支偏移改为 1540（`63 12 05 60`） |
| 去掉 Ctrl+Fn | `0x1D998` | `0x1E32C` | 原指令 `nds.bbc a5,2,-88` 改为 `j -88`（`6F F0 9F FA`），目标处代码与 0117 相同 |
| Win Fn 表 F1–F12 | `0x1F171`… | `0x1FB31`… | 数据槽，原值相同 |
| Mac 媒体表 F1–F12 | `0x1F1D9`… | `0x1FB99`… | 数据槽，原值相同 |

反汇编需要支持 Andes 扩展的 LLVM（`llvm-objdump --mattr=+xandesperf`；Xcode 自带的 LLVM 没有 RISC-V），汇编编码用 `llvm-mc`。补丁位置与原始字节都与官方 0102 镜像逐字节核对过（`PIXIU75PokemonDefinitionTests`，官方升级包存在时运行），但没有真机，全部标为实验性。

## 取舍

- **识别范围**：驱动设备表中的全部键盘（44 个 PID）和键盘接收器。鼠标、鼠标垫只显示 USB 信息。驱动中 PID 为 0 的 7 个条目（G80-3000N 等）无法按 PID 识别，不收录。
- **已验证与推断分开**：只有 PIXIU 75 标「已真机验证」，其他型号标「按官方驱动适配，未经真机验证」。
- **可编辑字段**严格按驱动写入范围；无背光型号不显示灯效，有线型号不显示休眠与电量。
- **电量（`0x1A`）与设备信息块（`0x1D`）只对无线型号读取**；有线型号的快照只含配置。
- **固件页**：Telink USB_OTA 型号照常刷写；其他型号显示当前版本、官方目录最新版本和固件家族，说明需用官方 Windows 升级程序。
- **配置档数量**沿用 3（驱动里没有按型号区分配置档数量）。

## 验证与风险

- 单元：`KeyboardCatalogTests`、`MultiModelServiceTests`、`MultiModelFeatureTests`、`MultiModelSimulationTests`。
- 模拟场景 `mx30s`（有线 RGB）、`nbl`（无背光）、`pixiu98`（B 型灯效表）、`receiver`（PIXIU 75 接收器），以及 UI 测试 UI-110–113 和意图测试 UI-128–131（见 [UI 测试用例](ui-tests.md)）。
- 除 PIXIU 75 外没有任何真机，所有「按驱动推断」的功能都可能因固件差异失败；读写失败时 App 报错，但不会写入驱动范围以外的字节。
- Sonix 有线型号是否实现 `0x1D`、配置档数量是否为 3，均未确认。
- 接收器转发配置依赖键盘在线，键盘关机时读写会超时。
